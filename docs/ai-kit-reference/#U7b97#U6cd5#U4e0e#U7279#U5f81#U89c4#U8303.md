# 算法与特征规范

以随包 `reference_predictor/core/raw_features/chart.py`、`event_features.py` 为可执行定义，权重 JSON 内的 `event_contract` 确定特征顺序。下列规范描述当前 events_stats 实际输入，不应替换成旧工作台的秒窗口特征。

## 1. 解析、时间与几何

要求 `formatVersion == 3`，至少一个音符。Tap=1、Drag=2、Hold=3、Flick=4。输入数字必须有限。每条线有自己的 BPM，必须大于零。

- 音符时间：`time = round(tick * 1.875 / bpm + offset, 9)`，单位秒。
- Hold 结束：`round(time + holdTime * 1.875 / bpm, 9)`。其他音符结束即开始。
- Python 的 round 是最接近值、恰好中点取偶数；移植时需注意浮点与十进制舍入差别，禁止自行增加同时判定容差。
- 按 `(time, line_index, side, positionX, type, end)` 排序，再按**舍入后完全相同的 time**分组。同时间多线音符属于同一组。
- 上侧 `side=+1`，下侧 `side=-1`。
- 加权按键数：Tap=1、Hold 头=1、Flick=0.5、Drag=0。

线事件先按开始时刻排序。相邻区间端点误差大于 1e-6 则拒绝；线位置、旋转按区间线性插值，区间外沿用端部状态。普通查询在边界取新事件；速度查询在边界取前一事件（`before=True`）。缺省移动为 (.5,.5)、旋转 0、速度 1、透明度 1。

只有速度事件允许跳过零时长区间，并且必须仍有有效正时长速度区间；全部为零时长或反向区间均报错。该处理不改原始 JSON，也不改用于模型选择的身份哈希。

坐标以画面宽度为单位，原点左下。固定 `aspect = 1.777778`，使用训练值，不能换成用户设备实际比例。角度正向和单位遵从原解析器：

```
d = positionX * 0.05625
hit_x = line_x + d * cos(rotation)
hit_y = line_y / aspect + d * sin(rotation)
```

这里 rotation 计算三角函数前由度转弧度。下落方向：取打击时的判定线速度；非 Hold 再乘音符 speed，Hold 不乘。若速度绝对值小于 1e-12，方向未定义；否则 `angle = (rotation - 90 * side + (速度<0 ? 180 : 0)) mod 360`。这是法线方向代理，不是移动线与下落叠加后的实际速度方向。

0.15 秒前锚点使用同一音符的 positionX、该时刻的线位置/旋转。这个锚点不是屏幕上尚未落下的音符位置。`floorPosition` 被读取，但不进入本模型特征；透明度用于事件校验，不进入模型特征。当前版本没有把所有视觉干扰都完整建模。

## 2. 17 维音符特征

下表顺序不可调整。`signed_log(v) = sign(v) * ln(1+abs(v))`。

| 序号（从 0 开始） | 名称 | 定义 |
|---|---|---|
| 0～3 | tap, drag, hold, flick | 四类 one-hot |
| 4～5 | hit_x, hit_y | 打击锚点 |
| 6 | log_hold_seconds | ln(1+结束时间−开始时间) |
| 7～8 | angle_sin, angle_cos | 下落方向的正弦与余弦；未定义时均为 0 |
| 9 | angle_defined | 方向是否已定义，0/1 |
| 10 | side | +1 或 -1 |
| 11 | signed_log_note_speed | 音符自身 speed 的 signed_log |
| 12 | signed_log_line_speed | 打击时线速度的 signed_log，不乘音符 speed |
| 13～14 | anchor_dx_015, anchor_dy_015 | 当前锚点减去 0.15 秒前锚点 |
| 15～16 | rotation_delta_sin_015, rotation_delta_cos_015 | 线旋转在 0.15 秒内变化量的正弦与余弦 |

## 3. 同刻组与 6 维特征

记第一个组时间为 t0，全部音符最晚结束为 end，`duration=max(end-t0,0.001)`。每组记录前先删除结束时间 <= 当前时刻的活动 Hold；当前组新 Hold 在记录后才加入，所以同组 Hold 头不算“之前已占用”。

| 序号 | 名称 | 定义 |
|---|---|---|
| 0 | log_gap_seconds | ln(1+当前组与前一组时间差)，第一组为 0 |
| 1 | log_elapsed_seconds | ln(1+当前组时间−t0) |
| 2 | time_progress | (当前组时间−t0)/duration |
| 3 | log_note_count | ln(1+组内音符数) |
| 4 | log_press_weight | ln(1+组内加权按键数) |
| 5 | log_active_holds | ln(1+该组开始前活动 Hold 数) |

额外数组：`note_groups[N]` 为连续的从 0 开始组编号；`group_times[G]` 为减 t0 的秒数；`group_durations[G]` 为与下组的时间差，最后一组用 `max(end,最后组时间+0.001)−最后组时间`。不得将最后一项改成 0。group_times 本身不进入网络 forward，group_durations 参与汇总。

## 4. 18 维整谱统计

全部统计针对原谱有效音符区间，不使用音频时长或文件名标签。所有分位数使用 NumPy 默认线性插值：排序后索引 `(n-1)*q`，相邻两项线性加权；空列表分位数为 0。

| 序号 | 名称 | 定义 |
|---|---|---|
| 0 | log_duration | ln(1+duration) |
| 1 | log_note_count | ln(1+总音符数) |
| 2 | note_rate | 总音符数/duration |
| 3 | press_rate | 总加权按键数/duration |
| 4 | press_1s_max | 每个组时间 t 上，(t−1,t] 内加权按键数的最大值 |
| 5 | press_1s_p90 | 上述各组采样值的 90% 分位数 |
| 6～9 | tap_fraction, drag_fraction, hold_fraction, flick_fraction | 对应类型音符数/总音符数 |
| 10 | hold_coverage | 至少 1 个 Hold 持续的时间并集/duration |
| 11 | hold_overlap_coverage | 至少 2 个 Hold 同时持续的时间/duration |
| 12 | chord_group_fraction | 音符数>1的组数/总组数，包含 Drag |
| 13 | max_chord | 单组最大音符数 |
| 14 | press_gap_p50 | 加权按键数>0的相邻组时间差中位数 |
| 15 | press_gap_min | 上述差值最小值；没有间隔为 0 |
| 16 | long_gap_fraction | 上述差值中大于 1 秒的**完整间隔**之和/duration |
| 17 | hold_seconds_per_second | 所有 Hold 持续秒数之和/duration，可能大于 1 |

提取器还保留 `motif` 和 `margin` 历史实验计算以及双指模拟代码，方便复现原管线。这两类数组**没有输入 events_stats 网络**。原生移植可不执行它们，前提是 17/6/18 维输入和组持续时间已对齐。旧分段参数及近似重合判定线参数也不作为当前网络的输入。

## 5. 逐模型标准化

每个权重对应自己的 `preprocessor`。对 events、group_features、stats 三类数组，各列用 `(value−mean)/scale`。提取和标准化用 float64，然后转 float32 进入网络。scale 小于阈值的处理已在训练拟合阶段完成，不要推理时重新拟合、改 scale 或裁剪特征。

组编号 int64；组持续时间直接转 float32，不标准化；group_times 不标准化。不要给全部 15 模型使用同一份平均数/标准差。

## 6. 身份、选择与输出

参考哈希：`SHA256(json.dumps(raw, ensure_ascii=False, sort_keys=True, allow_nan=False, separators=(',', ':')).encode('utf-8'))`。注意 Python 对浮点 JSON 的输出格式；跨语言 JSON 序列化不一定完全一致，1 与 1.0 也可能产生不同身份。合成测试向量附上期望哈希。

开发集 467 个身份每个对应三个未训练过它的折外模型，取其预测均值；83 个保留集身份和其他身份默认使用全部 15 模型。未知哈希不保证内容在玩法上从未见过。开发集身份由模型记录给出，不需要歌曲名/定数。跨语言若无法复现哈希，必须明确选择使用全部模型，不能宣称保持了折外规则。

结果不使用曲名、难度名、文件名定数或 info.txt 标签。模型输出不截断、不作函数校准、不提前四舍五入。只在界面显示时格式化，存储仍保留原浮点值。

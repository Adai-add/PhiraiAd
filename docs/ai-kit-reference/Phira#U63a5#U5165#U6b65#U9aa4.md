# Phira 改版接入步骤

本包不假定你的 Phira 改版目录结构。以下是应用层应实现的契约，Python 参考可直接运行；Rust/Android 需要实现对应模块，或自行接入可执行 Python 的环境。本包未提供移动端运行时。

## 接口边界

建议原生提供 `predict_chart(raw_chart_bytes, bundle, selection)`，返回至少：

```json
{
  "sample_id": "规范化原谱哈希",
  "predicted_constant": 16.84994888305664,
  "model_std": 0.03987684780675151,
  "model_count": 3,
  "scope": "development_oof",
  "models": [{"seed":42,"fold":5,"prediction":16.899581909179688,"seen_in_training":false}]
}
```

这是一个真实谱面的返回形式示例，models 在实际输出中应包含全部选中模型。分析器只需要原版 JSON，不需要文件名定数、音频或玩家分数。

在 Rust 中可用 `Vec<f32>` 存连续 row-major 张量，用 `f32::from_le_bytes` 读二进制，用 `f64` 计算时间、几何、统计和标准化。矩阵乘法可以手写或使用你工程已有的线性代数实现；对应权重布局和公式见另一份文档。不要尝试把本包自定义 BIN 当作 ONNX/TFLite 模型。

## 移植顺序与通过条件

1. 读取 manifest，校验 15 个权重的哈希、索引和 config；为每个模型加载独立 preprocessor。
2. 用 `test_vectors/*.raw.json` 实现 format3 解析，比较对应 `*.features.json`。先对齐音符顺序、时间分组、坐标和 17/6/18 个特征，不要先调网络输出。
3. 用保存的 features 绕过解析，逐模型跑网络，对照 `*.expected.json` 的 15 个单模型输出，绝对差小于 1e-4。
4. 接回原谱解析，验证均值与模型选择；已知开发谱使用 OOF 模式时必须复现 Python JSON 哈希规则。端上不能复现身份时，可显式统一 all15，但要标明评估语义发生变化。
5. 在 Android 目标设备测试延时、内存、异常输入、取消与后台任务。包内 CPU 一致性结果不替代端上验证。

原谱输入支持范围要在 Phira 界面中明确：不能将 RPE/PEC JSON 按 format3 解析。你可以在已有谱面解析层导出等价的本包输入数组，但前提是数值契约逐项一致；仅取得音符列表不够，还需要打击时以及前 0.15 秒的判定线几何。

## 执行与缓存

建议在曲目详情页或导入后触发后台预测，避免每帧和音符判定线程运行网络。一次提取原谱，逐模型使用各自的标准化参数预测。模型加载后复用；未知谱默认 15 个小模型连续运行。

缓存键至少包含：原谱内容哈希、特征实现版本、全部模型资产版本/哈希、selection。不能只按文件名缓存。使用动态改速、镜像或其它玩法修饰时，当前接口仍按原谱预测；如要支持修饰后定级，须定义并重新验证转换，禁止简单按倍速乘预测值。

有解析错误时返回明确错误，界面显示“无法预测/格式不支持”，不要用 0 或文件名定数作为预测替代。对模型校验失败同样报错。

## 当前方案未使用的旧功能

GUI、批量文件扫描、ZIP 读取、区间偏差评估可供桌面排查；不是端上网络算子。源码保留了历史 motif/margin 及双指路由计算以便完整复现提取器，但当前 events_stats 只消费事件、组特征、组持续时间和整谱统计。移植时可以省去未消费的计算，而不能删除真正的 18 维统计分支。

当前无函数校准器、无网络下载、无自动训练、无训练参数更新。模型间标准差只说明分歧，不能显示成“±某数保证范围”。
